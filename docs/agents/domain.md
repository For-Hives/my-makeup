# Documentation de domaine

Comment les skills d'ingénierie lisent la documentation de domaine de ce dépôt (contexte unique).

## À lire avant d'explorer

- **`CLAUDE.md`**, sections « Conventions » et « Glossaire des noms », et [`docs/noms.md`](../noms.md) : le vocabulaire du code. Il tient lieu de `CONTEXT.md`, qui n'existe pas encore.
- **`docs/migration/`** : le schéma (`SCHEMA.md`), les adresses (`URLS.md`) et le registre des changements voulus (`CHANGEMENTS-VOULUS.md`).
- **`docs/adr/`** : n'existe pas encore. Les décisions de conception vivent dans les documents de `docs/`.

Si un de ces fichiers manque, continue sans le signaler.

## Vocabulaire

Le code est en anglais jusque dans ses noms, les textes visibles sont en français. Dans un titre d'issue, utilise le mot du glossaire (« profil », « prestation », « zone », « publiable »), pas un synonyme.

## Conflits avec une décision

Si un travail contredit une décision écrite (registre des changements voulus, guide), dis-le explicitement au lieu de la passer sous silence.
